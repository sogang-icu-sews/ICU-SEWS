# ICU-SEWS LightGBM·LSTM·GRU 앙상블 보고서

- 작성일: 2026-11-24 (KST)
- 담당: 정상민 — 데이터 파트
- 비교 대상: LightGBM, LSTM, GRU 단일 모델(각각 Optuna 탐색) + 같은 가중치 앙상블 + Optuna 가중치 앙상블
- 실행 이름: `ens_v1` (`notebooks/ICU-7_ensemble.ipynb`, 같은 계산: `data/models/train_ensemble.py`)
- 평가 범위: 단일 모델 Optuna 탐색, 개발 5-fold OOF 비교, 보정·경보 임계값 설정, 고정 test 평가

## 1. 결과 요약

세 모델의 하이퍼파라미터를 Optuna로 탐색하고, logit 가중 평균 앙상블을 만들었다.
환자 역할은 팀 최종 GRU(`final_gru.py`)의 `roles_for`를 그대로 써서 최종 모델·보정·임계값·test가
팀 최종 GRU v2와 **같은 환자 구성**이다. 따라서 test 점수를 팀 최종 GRU와 직접 비교할 수 있다.

최종 test는 **6,051명, 233,321개 시간 행**이다.

| 지표 (test) | 팀 최종 GRU v2 | LightGBM | 앙상블 (Optuna 가중치) |
|---|---:|---:|---:|
| AUROC | 0.7632 | 0.7936 | **0.7941** |
| AUPRC | 0.0703 | 0.0746 | **0.0809** |
| Brier (보정) ↓ | 0.01718 | 0.01714 | **0.01706** |
| Utility | 0.1214 | 0.1441 | **0.1748** |
| 비패혈증 환자 오경보율 | 9.30% | 8.63% | 9.07% |
| 추정 발병 전 0~12시간 감지율 | 27.6% | 31.1% | **32.6%** |
| 감지 환자의 선행 시간 중앙값 | 8시간 | 8시간 | 9시간 |

- 앙상블은 팀 최종 GRU보다 비슷한 오경보율에서 AUROC +0.031, AUPRC +0.011, Utility +0.053,
  조기 감지율 +5.0%p 높다.
- **행 단위 AUROC 목표 0.82에는 도달하지 못했다** (dev 5-fold 최고 0.804, test 0.794).
- 앙상블과 최고 단일 모델(LightGBM)의 test AUROC 차이는 0.0005로 의미가 없다.
  앙상블의 이점은 AUPRC·Utility·조기 감지율에서 나온다.
- Optuna 가중치 앙상블과 같은 가중치(1/3씩) 앙상블의 성능이 사실상 같다
  (dev AUROC 0.8038 대 0.8032). 가중치 최적화로 얻은 이득은 거의 없다.
- 신뢰구간은 아직 계산하지 않았다. 위 차이가 우연인지는 환자 단위 bootstrap으로 확인해야 한다 (8장).

## 3. 설계

### 3.1 환자 역할과 단계

| 단계 | 쓰는 환자 | 목적 |
|---|---|---|
| ① 단일 모델 Optuna 탐색 | dev fold 0~2 학습 → fold 3 검증 | 모델별 하이퍼파라미터, 학습 길이(epoch·반복 수) |
| ② 5-fold OOF | dev 34,285명: fold k를 빼고 학습 → fold k 예측 | 기존 결과와 같은 기준의 비교 |
| ③ 앙상블 가중치 | 교차 적합: fold k 평가용 가중치는 나머지 4개 fold의 OOF로 찾는다 | 공정한 5-fold 앙상블 점수 |
| ④ 최종 모델 | fold 4 모델 = fold 0~3(27,428명)으로 학습 | 팀 최종 GRU와 같은 학습 환자·스케일링 통계 |
| ⑤ 보정·임계값 | fold 4를 반으로: 보정 그룹 3,428명(Platt) / 임계값 그룹 3,429명 | 경보 규칙: 비패혈증 환자 오경보율 10% (팀 GRU와 같음) |
| ⑥ test | 6,051명, 한 번만 | 최종 성능 |

최종 가중치는 fold 0~3의 OOF(패혈증 환자 약 2,000명)로 정했다. 이 값은 ③에서 fold 4를 평가할 때 쓴 가중치와 같다.

### 3.2 모델

- **LightGBM**: 데이터 파트 특징 125개 (최근 24시간 통계·SOFA·qSOFA·측정 패턴, ICULOS 없음). 결측은 LightGBM이 직접 다룬다.
- **LSTM**: ICU-6 구조. 24시간 창 66채널(값 24 + 측정 여부 21 + 마지막 측정 이후 시간 21) + 정적 변수 5개.
- **GRU**: 팀 `GruSepsisModel`과 Adam. 같은 창에서 패딩을 제외한 가변 길이 입력 + 정적 변수 5개.
- **앙상블**: Σ w·logit(p), w ≥ 0, Σw = 1. 세 모델의 확률 척도가 달라 logit 공간에서 더한다.

Optuna 탐색의 첫 trial은 지금까지 쓴 설정(LightGBM: ICU-3 기준선, LSTM: ICU-6, GRU: 팀 최종 v2)이다.
목표는 행 단위 AUPRC다 (팀 GRU도 검증 AUPRC로 골랐다).

### 3.3 누수 방지

- 스케일링 통계는 그 단계의 학습 행에서만 구했다. fold별 통계가 데이터 파트 `preprocess_params/fold{k}.json`과
  같은지 실행 중에 확인했다.
- GPU에서 만든 창이 데이터 파트 `seq_windows`(LSTM)·팀 `pack_inputs`(GRU)와 같은지 실행 중에 확인했다.
- 교차 적합 가중치는 평가 fold의 라벨을 섞어도 바뀌지 않음을 별도 검증으로 확인했다.
- 최종 모델·가중치·보정·임계값을 `frozen.json`으로 고정한 뒤 test를 한 번만 평가했다.

## 4. 개발 5-fold 결과 (dev 34,285명, 행 단위)

| 모델 | AUROC | AUPRC | AUROC (ICULOS ≤ 60) |
|---|---:|---:|---:|
| LightGBM | 0.7974 ± 0.0062 | 0.0787 ± 0.0039 | 0.7885 ± 0.0092 |
| LSTM | 0.7870 ± 0.0088 | 0.0785 ± 0.0043 | 0.7747 ± 0.0052 |
| GRU | 0.7895 ± 0.0102 | 0.0789 ± 0.0050 | 0.7778 ± 0.0142 |
| 앙상블 (같은 가중치) | 0.8032 ± 0.0077 | **0.0867 ± 0.0051** | 0.7927 ± 0.0090 |
| 앙상블 (Optuna 가중치) | **0.8038 ± 0.0077** | 0.0866 ± 0.0051 | **0.7935 ± 0.0090** |
| 참고: 기존 LSTM (ICU-6, 튜닝 전) | 0.7773 ± 0.0137 | 0.0716 ± 0.0066 | 0.7644 ± 0.0171 |

- Optuna 탐색으로 LSTM은 0.777에서 0.787로 올랐다 (같은 행, 같은 fold).
- 앙상블은 최고 단일 모델보다 AUROC +0.006, AUPRC +0.008 높다.
- ICULOS ≤ 60 AUROC가 전체와 0.01 안팎으로 차이 나서, 기록 길이 지름길에 기대지 않는다.
- 기존 로지스틱 회귀(ICU-5)는 실행 환경에서 OOF 파일을 찾지 못해 표에서 빠졌다. 기존 점수는 0.769 ± 0.008이다.
- 탐색 검증에 fold 3을 썼으므로 fold 3 점수는 조금 낙관적일 수 있다.

## 7. 해석

- **팀 최종 GRU 대비**: 같은 환자 구성에서 Optuna로 탐색한 GRU 단독도 test AUROC 0.775로 v2(0.763)보다 높다.
  앙상블은 모든 지표에서 팀 최종 GRU보다 좋다.
- **dev → test**: 앙상블 AUROC가 0.804에서 0.794로 0.01 낮아졌다. fold 간 표준편차와 비슷한 크기라서
  과적합의 근거로 보기 어렵다.
- **가중치**: Optuna 가중치와 같은 가중치의 AUROC 차이는 dev·임계값 그룹·test 모두 0.0015 이하다.
  발표에서는 "단순 평균으로도 같은 성능"이라고 설명하는 것이 정확하다.
- **병원 차이**: 하나의 임계값을 두 병원에 쓰므로 병원 A의 오경보율(12.3%)이 B(5.9%)의 두 배다.
  팀 최종 GRU 보고서와 같은 양상이다.
- **0.82 목표**: 현재 수치는 모두 시간별(행 단위) AUROC다. 목표의 평가 단위(행/환자)를 사양서에서 확인한다.
  test를 본 뒤에 단위를 바꿔 고르지 않는다.

## 8. 한계와 후속 과제

- 신뢰구간이 없다. 팀의 환자 단위 bootstrap(`scripts/bootstrap_gru.py`)을 같은 test 예측에 적용해
  팀 최종 GRU 대비 향상이 우연인지 확인한다.
- 단일 분할·단일 seed 결과다. 탐색은 fold 3 하나로 검증했다.
- 개발 데이터(fold 0~4)가 탐색·가중치·보정·임계값 선택에 쓰였다. 팀 최종 GRU가 같은 test를 이미 한 번 평가했다.
- 경보는 매시간 플래그이며 cooldown을 적용하지 않았다. 알림 횟수가 아니다.
- 이 결과를 보고 모델·가중치·보정·임계값을 바꾸지 않는다. 바꾸려면 새 실행 이름으로 dev 안에서만 고르고,
  test 재사용 사실을 보고서에 밝힌다.

```bash

```

노트북과 스크립트는 같은 데이터에서 같은 결과를 내는 것을 확인했다. 끊겨도 다시 실행하면 끝난 trial·fold·고정값을 읽어 이어 간다.
