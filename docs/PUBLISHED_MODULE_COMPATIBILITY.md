# 기존 데이터 및 최종 GRU 모델과의 코드 호환성

2026-11-15 PR #8 병합 시 CI에서 GRU 테스트 8개가 실패했다. `main`에 들어간
전처리 모듈의 서식·설명문 변경으로, 데이터에 기록된 SHA-256과 현재 코드가
일치하지 않았기 때문이다. 최종 GRU 실행은 평가 모듈의 코드 해시도 검증한다.

## 수정 범위

다음 3개 파일을 기존 GRU 학습 브랜치의 `59c7379` 버전으로 복원했다.

- `data/src/sews_features.py`: 정제 및 특징 생성
- `data/src/sews_preprocess.py`: 스케일링 및 시계열 창 생성
- `data/src/sews_eval.py`: 평가 지표 계산

복원 전후 Python 구문 트리를 비교했으며, 주석·문서 문자열과 위치 정보를
제외한 실행 구문이 세 파일 모두 동일했다. 계산 로직을 변경하는 수정이 아니다.

`pyproject.toml`에서 이 세 파일만 자동 서식 대상에서 제외하고, 린트는 줄 길이
규칙(E501)만 예외로 두었다. 나머지 린트와 모든 테스트는 계속 실행한다.
`tests/test_published_module_identity.py`는 학습 없이도 세 파일의 해시를 검증한다.

## 기존 데이터와 모델 보존

- `artifacts/feature_registry.json` 및 전처리 설정·파라미터를 수정하지 않는다.
- 환자 분할, 전처리 데이터, 모델 가중치, Platt 계수, 경보 임계값을 수정하지 않는다.
- `train_gru.py`, `final_gru.py`의 해시 검증이나 최종 모델 동결 검증을 완화하지 않는다.
- 기존 Colab 최종 실행은 저장된 코드 커밋과 환경을 그대로 사용한다. 이 수정 때문에
  기존 결과 폴더를 덮어쓰거나 학습·test 평가를 다시 실행할 필요는 없다.
- 복원한 소스의 해시는 LF 줄바꿈 기준이다. 최종 실행의 엄격한 코드·라이브러리
  버전 검증은 유지되므로, 다른 OS/패키지 환경에서 기존 실행을 재개하는 것은 별도 문제다.

## 이후 전처리 로직을 변경할 때

이 파일은 배포된 데이터와 모델이 참조하는 버전이다. 서식 정리만을 이유로
수정하거나 기존 레지스트리·동결 정보를 새 해시로 덮어쓰지 않는다. 실제 계산을
바꾸려면 새 버전의 코드·데이터·모델을 함께 관리하고, 기존 실행의 코드와 결과는
보존한다. 그때 호환성 테스트의 기대값도 해당 버전 정책에 맞게 검토한다.

## 검증 결과

- Python 3.10 로컬 환경: 전체 테스트 60개 통과.
- `ruff check .`, `ruff format --check .`, `git diff --check` 통과.
- 복원한 3개 모듈과 GRU 학습·최종 평가 코드는 `59c7379`의 해당 파일과 동일하다.
- 테스트는 임시 합성 데이터를 사용한다. Drive에 저장된 실제 최종 모델을 다시
  학습하거나 test 평가하지 않았으며, 기존 결과 파일도 수정하지 않았다.
